# Cue - OpenAPI & Swagger Documentation Builder

Cue is a Next.js API documentation builder that helps teams import OpenAPI and Swagger specs, curate endpoints, edit request/response details, and export polished markdown docs fast.

If you are searching for an OpenAPI documentation generator, Swagger to markdown converter, API endpoint selector, or API schema-to-doc workflow for frontend teams, this project is built for that exact use case.

## Why Cue

Most API documentation workflows break down in one of two places: parsing and editing. Cue handles both. 

- Parse OpenAPI 3.x and Swagger 2.x from JSON or YAML
- AI Agent First, documentation generated by Cue provides AI agents full content of the API structure for full proof integration with frontend. 
- Import specs from file upload, raw pasted content, or documentation URL
- Auto-resolve nested `$ref` schemas into readable JSON examples
- Select and group endpoints before export
- Edit endpoint summaries, descriptions, parameters, and payload examples
- Generate downloadable markdown API documentation in one click


## Core Features

### 1. Multi-Source API Spec Import

Cue supports three input paths:

- Upload `.json`, `.yaml`, or `.yml` spec files
- Paste raw OpenAPI/Swagger text directly
- Provide a docs URL and auto-discover nearby spec files like:
	- `openapi.json`
	- `openapi.yaml`
	- `swagger.json`
	- `swagger.yaml`

### 2. OpenAPI + Swagger Parsing

The parser detects and normalizes:

- OpenAPI 3.x (`openapi: 3.x`)
- Swagger 2.x (`swagger: 2.x`)

Each endpoint is converted into a consistent internal model with:

- HTTP method and path
- Summary and description
- Parameters and required flags
- Auth configuration (Bearer, Basic, API Key)
- Request body example/schema output
- Response body example/schema output
- Tags and operation ID

### 3. Schema Resolution for Real-World Specs

Cue resolves deeply nested schemas so docs are readable, not just `$ref` placeholders.

- Recursive `$ref` resolution
- Handles `allOf`, `anyOf`, and `oneOf`
- Circular reference protection
- Depth limiting for safety
- Type-aware example generation for common scalar formats

### 4. Endpoint Curation and Editing UI

The UI includes:

- Searchable endpoint catalog
- Endpoint grouping strategy based on path, versioning, and tags
- Select all / deselect all controls
- Group-level selection controls
- Endpoint detail modal with edit controls
- Desktop and mobile selected-endpoints sidebar

### 5. Markdown Documentation Export

Generated output includes:

- Title and generation metadata
- Total selected endpoint count
- Per-endpoint sections
- Parameters table-style bullet output
- Authentication details
- Request and response JSON code blocks
- Tag visibility for discoverability

## How It Works

1. Import an API spec (file, paste, or URL)
2. Parse and normalize endpoints
3. Resolve request/response schemas
4. Search and select endpoints
5. Edit endpoint content in-place
6. Export markdown documentation

## Local Development

### Prerequisites

- Node.js 20+
- pnpm (recommended, lockfile included)

### Install

```bash
pnpm install
```

### Run Dev Server

```bash
pnpm dev
```

Open `http://localhost:3000`.

### Build

```bash
pnpm build
```

### Start Production Build

```bash
pnpm start
```

### Lint

```bash
pnpm lint
```

## NPM Scripts

- `dev` - Start Next.js dev server
- `build` - Build production app
- `start` - Start production server
- `lint` - Run ESLint
